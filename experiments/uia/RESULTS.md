# UIA（辅助功能接口）能否代替 / 补充 OCR：实测结果

2026-10-26，分支 `exp/uia-probe`。只读本实验自己启动的窗口，内容全部是合成数据（`fixtures.py`）。

## 环境

- Windows 11 Pro for Workstations 26200，i5-12600KF，32 GB，3840×2160 @150%（程序为 Per-Monitor V2，坐标都是物理像素）
- 读 UIA：`comtypes==1.4.17` 直接调系统 UIAutomationCore（CUIAutomation8，整棵树一次缓存取回）。没用 `uiautomation` 包：它一 import 就把进程 DPI 改成旧模式
- 对照：项目自己的 `capture_window`（PrintWindow）+ `OcrEngine`（RapidOCR 1.4.4，2 线程）；文字比对用 `rapidfuzz==3.10.1`
- 版本：Edge 156.0.4314.42，Chrome 156.0.8078.47，VS Code 1.143.1，Office 16.0.20527，记事本 11.2607.14，Windows Terminal 1.24.12741
- 测试时另有 OCR 基准在跑，CPU 很忙：耗时只作参考。同一窗口 OCR 一次 5–12 s，UIA 一次 0.03–0.35 s

## 怎么读这几张表

- **覆盖率**：OCR 读到的字有多少能在 UIA 文字里找到（按字符算）；括号里是反方向：UIA 给出的字有多少出现在截图里
- UIA 文字 = 控件树里"屏幕上可见"的正文类元素（未标 IsOffscreen、矩形和窗口相交、不是密码框），加上 TextPattern 的"可见范围"逐行文字
- **位置**：UIA 矩形减去截图左上角后，和 OCR 框比。能对上，高亮可以直接用
- 原始数字在 `results/<app>.json`；Office 和资源管理器的界面里有账号或用户自己的文件夹名，这几个文件不保存文字示例

| 网址 / 文件名 | 窗口名和标签名有文件名（`sr-uia-notes.txt`），没有完整路径 |

## 没测的

- 微信、QQ、邮件客户端、Teams / 钉钉 / 飞书等需要登录的程序：要用测试账号再测
- 大型网页应用（在线文档、长聊天记录页）上浏览器开启辅助功能的 CPU / 内存开销
- 不支持 DPI 的老程序（截图是逻辑像素，UIA 矩形要换算）、多显示器不同缩放
- 已保存的 Word 文档能否拿到完整路径

## 结论

**适合用 UIA 读文字的**：控制台和终端、记事本类编辑器、资源管理器、Edge / Chrome 网页、Word 正文、Excel 单元格。文字是原文，没有 OCR 的认错；每次 30–350 ms，比 OCR（5–12 s）快一到两个数量级；矩形和截图像素对得上，高亮能直接用。

**继续用 OCR 的**：VS Code（默认读不到代码）、画布 / 图片 / 视频里的字、游戏、远程桌面，以及任何 UIA 读出来很少的程序。网页上 UIA 也会漏掉画布和 `aria-hidden` 的字，所以网页最好两者合并。

**接入思路**：

1. UIA 必须在截图的同一时刻读，不能像 OCR 那样事后从图片补。截图后立刻在独立线程读一次，设好超时（`IUIAutomation2` 的连接 / 事务超时，每个程序再给预算），不能拖住采集循环。
2. 存进 `ocr_lines`，加一列 `source='uia'`，矩形减去截图左上角换算成图片坐标，搜索和高亮都不用改。
3. 只收"屏幕上看得见"的：去掉标了"屏外"的、矩形不和窗口相交的、密码框；文档和终端只取 TextPattern 的"可见范围"，不取 Value 或全文范围；窗口最小化时直接不读（浏览器自己不标"屏外"）。
4. 文字先去掉格式控制字符（U+200E 这类）。按钮、菜单的名字多是图标提示，屏幕上看不到，单独存或降权。
5. OCR 照常排队（优先级降低）。OCR 读到而 UIA 没有的行补进去；某个程序 UIA 覆盖一直很低，就只用 OCR。

**主要风险**：

- **浏览器第一次被访问**：只给外框，约 200 ms 后才完整。要么读到网页为空时稍后重读，要么保持连接。开启辅助功能后的长期开销在小页面上没看出来，大页面没测。
- **屏外文字**：文档全文、终端回滚记录、网页屏外段落都会被交出来。不过滤就会录下用户没看到的内容。
- **看不见的文字**：`sr-only` 这类只给读屏器的字会被收进来。
- **密码框**：浏览器只给圆点，但别的程序未必这样，必须按 IsPassword 过滤，不能依赖程序自己。
- **慢和卡**：Word 整树一次可达 3 s，VS Code 读屏模式下 3.2 s。不设超时会卡住采集。
- **读的是"那一刻"**：截图和 UIA 之间界面变了，两者会不一致（例子：计数器）。

## 文件

- `uia_core.py`：一次提取（整树缓存 + TextPattern 可见范围 / 逐行矩形）、可见过滤、与 OCR 的比对、矩形对位
- `fixtures.py`：合成内容（测试网页、记事本文本、代码、控制台输出、文件名、Word / Excel 内容）
- `probe.py`：逐个程序启动、摆放、截图 + OCR、多次读取、遮挡 / 最小化测试、关闭
- `results/*.json`：每个程序的指标
